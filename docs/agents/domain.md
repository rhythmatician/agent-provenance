# Domain Documentation

This repository uses a single domain context.

- `CONTEXT.md` contains canonical project-specific language only. It must not contain implementation details, work state, plans, file inventories, or algorithms.
- `docs/adr/` contains decisions that were hard to reverse, surprising without context, and selected through a genuine trade-off.
- Read `CONTEXT.md` before naming public interfaces, tests, issues, or graph entities.
- Treat accepted ADRs as constraints. Do not rewrite old ADRs to describe current behavior; supersede them when a later decision replaces them.
